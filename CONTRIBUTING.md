## Быстрый старт

1. Сделайте **Fork** репозитория
2. Склонируйте его и откройте папку `itmo-notebook/` как Vault в Obsidian или в другом редакторе
3. Внесите правки: дополните билет, исправьте опечатку, добавьте новую заметку
4. Перед созданием PR выполните нормализацию (см. ниже) и закоммитьте результат
5. Создайте **Pull Request** в `main`

Для правок без локальной установки можно воспользоваться веб-интерфейсом GitHub: скрипты всё равно ничего не сломают, CI просто попросит их прогнать.

## Оформление

### Имена файлов

Файлы заметок называйте на латинице (например, `question-1.md`), а отображаемый заголовок на русском указывайте в YAML-свойстве `title`. Это даёт корректные URL-адреса страниц.

### Ссылки

Используйте стандартные Markdown-ссылки `[текст](путь)`, а не вики-ссылки `[[путь|текст]]`.

Путь пишите **относительно текущей заметки** (без `.md` для заметок):

- `[текст](question-1)` -- файл в той же папке
- `[текст](../sem3/index)` -- файл в соседней папке
- `[текст](../../OPD/questions/question-1)` -- файл в другой ветке хранилища

Путь от корня хранилища (`[текст](matan/sem2/question-1)`) писать нельзя: он открывается в Obsidian только по угадыванию имени файла.

Пути `./` и `../` скрипт не трогает: ссылаться на файл, которого пока нет, легально.

**Исключение -- frontmatter.** Ссылки в YAML-полях (например, в `links:`) пишите от корня хранилища: `"[вопрос 27](matan/sem2/question-27)"`. Плагин `note-properties` резолвит их своим алгоритмом и не смотрит на настройку Quartz, поэтому относительный путь там ведёт в никуда.

Для вставок (трансклюзий) используйте тот же синтаксис с восклицательным знаком: `![текст](путь)`.

Если в пути есть пробелы, берите его в угловые скобки:

```markdown
[текст](<путь/с пробелами.md>)
![текст](<путь/с пробелами.png>)
```

### Изображения

Вставляйте картинки без принудительной ширины, если она не нужна по смыслу. Размер указывается **только в alt-тексте**, после вертикальной черты:

```markdown
![описание|200](Attachments/изображение.png)
![описание|200x150](Attachments/изображение.png)
![описание|x150](Attachments/изображение.png)
```

### Сноски

Сноски оформляйте через `[^1]` и `[^1]: текст`. Заголовок блока на сайте выводится как "Сноски", а обратная ссылка -- как "Вернуться к сноске N"; писать этот текст вручную не нужно.

### Формулы

Короткие формулы берите в одинарные `$`, длинные -- в двойные `$$`. Каждый `$$` занимает отдельную строку, без текста и пробелов рядом с разделителем: только тогда Quartz откроет display-блок. Внутри блока не должно быть пустых строк.

Inline-формулу не отделяйте пробелами от `$`: `$x + y$`, а не `$ x + y $`.

Нумерация через `\tag{...}` работает только в блочных формулах.

### Коллауты

Коллауты Obsidian разрешены, но не оставляйте их без названия: `> [!note] Определение` и т.п.

Допустимые типы: `note`, `info`, `todo`, `abstract`, `tip`, `success`, `question`, `warning`, `failure`, `danger`, `bug`, `example`, `quote`.

## Нормализация перед PR

Все проверки собраны в одном скрипте. Из **корня** репозитория выполните:

```bash
python scripts/normalize.py
```

Скрипт по очереди вызовет остальные:

1. [ensure_blank_after_embed.py](scripts/ensure_blank_after_embed.py) -- поставит пустую строку после вставок картинок и заметок
2. [convert_links.py](scripts/convert_links.py) -- преобразует вики-ссылки и перепишет пути на относительные
3. [check_math.py](scripts/check_math.py) -- вынесет каждый `$$` на отдельную строку

Устройство каждого скрипта и его отдельные ключи описаны в [README папки `scripts`](scripts/README.md).

Затем закоммитьте изменения. Требуется только Python 3, Node.js для этого шага не нужен.

Если хотите проверить, не меняя файлы:

```bash
python scripts/normalize.py --check
```

CI запускает ровно эту команду на каждом PR, поэтому PR с ненормализованным контентом не пройдёт проверку. Автоматических коммитов в ветки участников больше нет: бот пишет только в `main`.

> [!warning]
> Битая ссылка -- единственная ошибка, которую скрипт не исправляет сам. Он соберёт все такие ссылки, покажет файл, строку и причину и не изменит ни одного файла, пока вы не почините их вручную.

## Локальный предпросмотр сайта

Нужен [Node.js](https://nodejs.org/) версии 22 или новее. Из **корня** репозитория:

```bash
npm ci
npx quartz plugin install --from-config
npx quartz build --serve -d itmo-notebook
```

Одной строкой (Bash, zsh, Git Bash):

```bash
npm ci && npx quartz plugin install --from-config && npx quartz build --serve -d itmo-notebook
```

В PowerShell разделитель -- `;`:

```bash
npm ci; npx quartz plugin install --from-config; npx quartz build --serve -d itmo-notebook
```

Сайт будет доступен по адресу [http://localhost:8080](http://localhost:8080).

## Что делает CI

Workflow `.github/workflows/ci.yml` запускается на push в `main` и на обновлении PR. Пуш в свою ветку без открытого PR ничего не запускает -- событие `pull_request` появляется, когда PR уже создан.

- **PR** -- прогоняет тесты, проверяет, что контент нормализован, проверяет EditorConfig и собирает сайт без публикации. Ничего не коммитит.
- **push в `main`** -- нормализует контент, применяет EditorConfig и коммитит исправления в `main` от имени бота, после чего собирает и публикует сайт ровно из этого коммита.

Чтобы ошибка workflow блокировала слияние, добавьте его обязательной проверкой в правилах защиты ветки `main`: сам GitHub Actions не запрещает слияние при проваленной проверке, если для ветки такого требования нет.

## Тесты

```bash
python -m unittest discover -s scripts/tests -t .
npx tsx --test quartz/plugins/transformers/imageWidth.test.ts
```

Первая команда проверяет Python-скрипты, вторая -- плагин ширины картинок.
