# Оформление

Эта заметка описывает правила оформления заметок хранилища. Автоматически исправляемые требования применяются командой `python scripts/main.py`; остальные нужно соблюдать при написании.

## Ссылки и имена файлов

Файлы заметок называйте латиницей, например `question-1.md`. Отображаемое название указывайте в свойстве `title`.

Используйте стандартные Markdown-ссылки `[текст](путь)`, а не вики-ссылки `[[путь|текст]]`. Для заметок пишите путь без расширения `.md`, для вложений -- с расширением. Путь должен быть относительным к текущей заметке:

- `[вопрос 1](question-1)` -- заметка в той же папке
- `[семестр 3](../sem3/index)` -- соседняя папка
- `[вопрос ОПД](../../OPD/questions/question-1)` -- другая ветка хранилища

Пути `./` и `../` уже относительны и не переписываются. Ссылаться на ещё не созданный файл допустимо.

В YAML frontmatter используйте путь от корня хранилища. Например: `"[вопрос 27](matan/sem2/question-27)"`. Плагин `note-properties` разрешает такие ссылки по собственным правилам, поэтому обычный относительный путь там не подходит.

Для вставок используйте Markdown-синтаксис с `!`: `![описание](путь)`. Пути с пробелами заключайте в угловые скобки:

```markdown
[текст](<путь/с пробелами.md>)
![описание](<Attachments/изображение с пробелом.png>)
```

## Изображения

Не задавайте размер принудительно, если он не нужен для материала. Ширину и высоту указывайте в alt-тексте после `|`:

```markdown
![описание|200](Attachments/image.png)
![описание|200x150](Attachments/image.png)
![описание|x150](Attachments/image.png)
```

Размер задаётся в alt-тексте, а не в пути: правильно `![описание|200](image.png)`, неправильно `![описание](image.png|200)`. Это правило работает и для Markdown-вставок, и для Obsidian-вики-вставок, если они встречаются до нормализации.

В таблице вертикальную черту размера экранируйте, чтобы она не стала разделителем столбцов:

```markdown
| Первая картинка           | Вторая картинка            |
| ------------------------- | -------------------------- |
| ![первая\|200](first.png) | ![вторая\|200](second.png) |
```

Если нужен больший контроль, допустим raw HTML, например `<img src="Attachments/image.png" width="400" alt="описание">`.

## Сноски

Оформляйте сноски через `[^1]` и `[^1]: текст`. Заголовок блока на сайте локализуется как «Сноски», а подпись обратной ссылки -- как «Вернуться к сноске N». Не добавляйте их вручную.

## Формулы

Короткие формулы пишите inline через `$`, длинные -- отдельным display-блоком через `$$`. Inline-формулу не отделяйте пробелами от `$`: `$x + y$`, а не `$ x + y $`.

Каждый `$$` занимает отдельную строку без формулы, текста или пробелов рядом. Внутри display-блока не оставляйте пустых строк. Между соседними блоками поставьте пустую строку или текст.

Правильно:

```markdown
$$
S(x) = \frac{f(x+0) + f(x-0)}{2}
$$
```

В цитатах и коллаутах префикс `>` ставится перед разделителем:

```markdown
> $$
> S_n(x) = \frac{1}{\pi} \int_{0}^{\pi} f(x-t) D_n(t) \, dt
> $$
```

Нумерацию `\tag{...}` используйте только в display-блоках. В inline-формулах она ломает отображение.

Выбирайте inline или display по тому, как формула должна выглядеть в тексте: короткая формула продолжает строку, длинная занимает отдельную. Учитывайте отображаемую длину выражения и число равенств.

Не помещайте LaTeX в заголовки: это ломает навигацию и оглавление. Одиночный знак доллара в прозе, например цена `$5`, не является формулой; переменные вроде `$PATH` заключайте в inline code.

После редактирования заметок запускайте `python scripts/main.py`. Скрипт автоматически форматирует разделители, но не исправляет смысловые ошибки. Подробности -- в [описании скриптов](https://github.com/sergeypugin/itmo-notebook/blob/main/scripts/README.md).

## Коллауты

Используйте поддерживаемые Obsidian callout-типы: `note`, `info`, `todo`, `abstract`, `tip`, `success`, `question`, `warning`, `failure`, `danger`, `bug`, `example`, `quote`. Не используйте другие типы: они могут отображаться как обычный `note` или ломать вёрстку.

Не оставляйте callout без названия. Например: `> [!note] Определение`. Название можно добавлять и к другим типам.

Сворачивайте блок только когда это помогает чтению: `-` делает его свёрнутым по умолчанию, `+` -- раскрытым. Длинное доказательство можно поместить во вложенный сворачиваемый callout.

## Стиль математических заметок

Старайтесь использовать заголовки вместо жирного выделения. В определениях пишите `**Название** — это ...`. Не помещайте LaTeX в заголовки. Если используете маркированный список, каждый пункт должен быть короче 50 отображаемых символов. Не используйте знак `§` без необходимости и избегайте вводных фраз вроде «Вычислим» или «Заметим, что».

Теоремы оформляйте callout-блоками. В условии отделяйте предпосылки от утверждения пустой строкой. Доказательство помещайте во вложенный callout, который можно свернуть. Не ставьте символ завершения доказательства.

Пример:

```markdown
> [!abstract] Первая теорема Больцано-Коши
> Пусть функция непрерывна в области.
>
> В области существует точка, в которой функция равна нулю.
>
> > [!note]- Доказательство
> > Текст доказательства.
```

Для лекционных заголовков сохраняйте исходную нумерацию, например `# 1.1`. Начинайте уровни заголовков с первого и делайте заголовки короткими.
