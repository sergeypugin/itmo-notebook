### DHCP (Dynamic Host Configuration Protocol) — автоматическое выделение адресов

Автоматическая выдача IP-адресов, масок подсети, шлюза и DNS-серверов клиентам при подключении к сети. Работает на **прикладном уровне**, использует протокол **UDP**.

**Процесс получения адреса (DORA):**

| Шаг | Название | Действие |
|-----|----------|----------|
| **1** | **Discovery** | Клиент отправляет **широковещательный** запрос DHCPDISCOVER, чтобы найти DHCP-сервер в сети. |
| **2** | **Offer** | DHCP-сервер отвечает предложением DHCPOFFER, в котором предлагает клиенту свободный IP-адрес из области (SCOPE). |
| **3** | **Request** | Клиент отправляет **широковещательное** сообщение DHCPREQUEST, принимая предложение и уведомляя все остальные DHCP-серверы, что его услуги не нужны. |
| **4** | **Acknowledgement** | Сервер подтверждает выдачу адреса пакетом DHCPACK, указывая срок аренды (время жизни адреса), маску подсети, шлюз и DNS. |

После получения DHCPACK клиент может использовать IP-адрес в течение указанного времени аренды. При необходимости он может продлить аренду, отправив новый DHCPREQUEST.

### DNS (Domain Name System) — сервис доменных имен

Преобразование удобных для человека символьных имен (например, `www.1cloud.ru`) в IP-адреса и обратно. Работает на **прикладном уровне**, использует **UDP** и **TCP**.

> *Иерархическая структура DNS:
> - Корневой домен — обозначается точкой (`.`).
> - Домены первого уровня (TLD): `.ru`, `.com`, `.org` и др.
> - Домены второго уровня: `.1cloud`, `.yandex` и т.д.
> - Далее идут поддомены и имена конкретных хостов.

**Процесс разрешения имени (прямое преобразование):**
1. Клиент отправляет запрос своему локальному DNS-серверу.
2. Если локальный сервер не знает ответа, он обращается к корневому DNS-серверу.
3. Корневой сервер перенаправляет к серверу первого уровня .
4. Сервер первого уровня перенаправляет к серверу второго уровня.
5. Сервер второго уровня возвращает точный IP-адрес запрошенного хоста \.
6. Ответ возвращается клиенту. Все промежуточные серверы кэшируют полученную информацию, чтобы ускорить ответ на будущие запросы.

**Обратное преобразование (IP → Имя):**
Используется специальный домен in-addr.arpa. Например, для IP-адреса `11.22.33.44` запрашивается запись `44.33.22.11.in-addr.arpa`. Это используется, например, при проверках почтовых серверов.

### Транспортный уровень
Обеспечивает связь между приложениями на конечных устройствах с помощью портов (Socket = IP-адрес + номер порта).

| Протокол                                | Характеристика                                                                                                                                           | Применение                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **TCP** (Transmission Control Protocol) | • handshake<br>• Отслеживает сессии, управляет перепосылкой потерянных сегментов<br>• Собирает сегменты в правильном порядке<br>• много служебных данных | HTTP, FTP, SSH, SMTP, Telnet                 |
| **UDP** (User Datagram Protocol)        | • без соеденения<br>• «Послал и забыл»<br>• без контроля надежности<br>• макс. скорость, мин. задержки                                                   | SNMP, TFTP, DHCP, DNS, потоковое видео/аудио |

**Ключевые функции транспортного уровня:**
- Отслеживание индивидуальных сеансов между приложениями (только для TCP).
- Сегментация данных и обратная сборка.
- Идентификация приложений по номерам портов (порт 80 — HTTP, 443 — HTTPS, 53 — DNS, 67/68 — DHCP).

### Прикладной уровень

Это верхний уровень модели TCP/IP. Здесь работают протоколы, с которыми непосредственно взаимодействуют пользовательские приложения.

Основные протоколы и службы:
- **HTTP/HTTPS** — передача гипертекстовых страниц (Веб).
- **FTP** — передача файлов.
- **SMTP/POP3/IMAP** — электронная почта.
- **DNS** — преобразование имен в IP-адреса.
- **DHCP** — автоматическая выдача IP-адресов.

Единица данных, которой оперирует прикладной уровень, называется сообщением.
