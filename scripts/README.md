# Скрипты для проверки и преобразования заметок

Запускай команды из корня репозитория.

## Преобразование ссылок

`convert_links.py` заменяет Obsidian-вики-ссылки на стандартные Markdown-ссылки, а пути уже написанных markdown-ссылок переписывает относительно каталога текущей заметки. Для заметок расширение `.md` отбрасывается, для вложений сохраняется. Ссылки `./`, `../` и абсолютные (`/`) скрипт не трогает: ссылаться на файл, которого пока нет, легально.

Если цель не найдена или неоднозначна, скрипт собирает **все** такие ссылки по всем файлам, печатает путь, номер строки, исходную ссылку и причину и в этом случае **не меняет ни одного файла** -- даже корректные ссылки в других заметках. Ненайденные и неоднозначные ссылки исправляются вручную.

Блок frontmatter скрипт пропускает. Ссылки в YAML-полях резолвит плагин `note-properties` своим алгоритмом, который не учитывает `markdownLinkResolution`, поэтому там нужна корневая форма (`[вопрос 27](matan/sem2/question-27)`), а не относительная -- иначе на сайте получаются битые ссылки.

Размер картинки в пути не разбирается: `![имя|200](файл.png|200)` -- это попытка открыть файл с именем `файл.png|200`, то есть ошибка. Правильно -- `![имя|200](файл.png)`.

Команда преобразования всех определённых ссылок:

```bash
python scripts/convert_links.py apply-all
```

Проверка без изменения файлов: выводит всё, что ещё не приведено к относительному виду (включая вики-ссылки, корневые пути и битые цели), и завершает работу с ошибкой.

```bash
python scripts/convert_links.py check
```

## Пустая строка после вставок

`ensure_blank_after_embed.py` ставит пустую строку после каждой вставки, то есть после строки, целиком занятой `![alt](путь)` или `![[файл]]`. Без неё следующий абзац прилипает к картинке. Внутри цитаты пустая строка получает тот же префикс `>`, иначе цитата рвётся.

Скрипт идемпотентен, не трогает frontmatter, fenced-блоки, обычные ссылки и случай, когда вставка -- последняя строка файла.

```bash
python scripts/ensure_blank_after_embed.py
```

## Исправление формул

`check_math.py` проходит по заметкам хранилища и ставит каждый `$$` на отдельную строку. Этого требует парсер Quartz: приклеенный к формуле разделитель он читает как inline-формулу, display-блок не закрывается и вбирает в себя заголовки и абзацы до следующего `$$`.

Скрипт не трогает заголовки, таблицы, строки с inline code, fenced-блоки и frontmatter. У inline-формул убирает пробелы сразу после открывающего и перед закрывающим `$`. Внутри цитат и коллаутов префикс `>` сохраняется. Файлы всегда перезаписываются с переводами строк LF.

В stderr скрипт печатает то, что нельзя исправить автоматически: LaTeX в заголовке, нечётное число `$` подряд и display-блок, не закрытый до конца файла. Одинокий `$` в прозе ошибкой не считается: это обычный знак доллара (`цена $5`, `$PATH`), рендер он не ломает.

```bash
python scripts/check_math.py
```

Проверка без изменения файлов: перечисленные проблемы дают код возврата 1. CI запускает её уже после коммита исправлений.

```bash
python scripts/check_math.py --check
```

## Тесты

Тесты скриптов лежат в `scripts/tests` и проверяют преобразование ссылок и вставку пустых строк на временных деревьях файлов:

```bash
python -m unittest discover -s scripts/tests -t .
```

Плагин ширины картинок проверяется отдельно от Python-скриптов:

```bash
npx tsx --test quartz/plugins/transformers/imageWidth.test.ts
```

## Автоматическая проверка в GitHub Actions

Workflow `.github/workflows/ci.yml` запускается на push и при обновлении PR и выполняет шаги в таком порядке: ставит пустые строки после вставок, преобразует ссылки, форматирует формулы, применяет EditorConfig, прогоняет тесты и коммитит исправления в текущую ветку. После push в `main` workflow собирает и публикует сайт, причём сборка идёт ровно из того коммита, который создал форматтер. Для PR собирается отдельная проверка без публикации.

Чтобы ошибка workflow блокировала слияние PR, добавь этот workflow как обязательную проверку в правилах защиты ветки `main`. Сам по себе GitHub Actions не запрещает слияние при проваленной проверке, если для ветки не настроено такое требование.

Инструменты для CI лежат в `scripts/package.json`, чтобы `eclint` не попадал в зависимости Quartz. Установка -- `npm ci --prefix scripts`, запуск -- `./scripts/node_modules/.bin/eclint`.

Для коммитов в `main` workflow использует встроенный `GITHUB_TOKEN` с правом `contents: write`. Автокоммит форматтера работает, когда ветка PR находится в этом же репозитории; для PR из форка он не запускается, потому что встроенный токен туда не пишет.
